# Subhasta

Subhasta (Latin *sub hasta*, "under the spear") is a single-file web app about the art trade: auction results, houses and the people who run them, a provenance ledger built from the National Gallery of Art's open data, the taxes, fees and rules that sit under a price, a members' board, an analyst you can ask, and fifty-eight art movements read as the market reads them. It is a terminal, not a feed: every figure is typed into the data files under `src/` (two more, the globe's dot mask and the Lab's benchmarks, are generated by scripts), carries a verification flag (V verified, S secondary, U unverified) and links its source; the Lab computes its measures from them at render. The build concatenates the data, the engines and the stylesheet into one HTML page (`build/rostrum.html`, about 2.4 MB with 771 provenance records, the world map, the globe and the movements inline) that is published as a private Claude artifact together with 117 public-domain pictures and the source tree. There is no framework, no bundler and no server; the page runs inside the artifact host (which blocks external fetches and images) and, with reduced features, from `file://`. See `ARCHITECTURE.md` for how it is put together and `REFRESH.md` for the monthly data refresh.

## The sections

The page opens on the World, a full-bleed globe (v23). The masthead lists ten sections — World, Library, Today, Ask, Movements, Sales (the Hammer), Market (the Pulse), Money (the Undertow), Navigator, Provenance (the Ledger) — and a More menu with the others (the Reel, Season, Horizon, Transformation, Deal Room, the ocean’s five — Tides, Collectors, Currents, Whispers, Playbooks (v27) — the desk’s four — The Brief, Worked cases, The Walls, Sources (v28) — Compare, the Lab, Atlas, Houses, People, Salon, Lexicon, Circle; the Desk, the owner's outreach workbench, shows only to the artifact's owner). **Signals** has no masthead button and is reached from Today, the palette, the Reel or `#signals`. The keys 1–9 open the first nine in that order. The palette (⌘K) searches everything, asks the analyst, and since v26 takes the terminal’s functions as codes — COMP Monet, EST Rothko, FEES 50m London, LAND London Geneva, DEAL 50m, TRX 3m Bangladesh, VLT Geneva, NET Paris, WHO Gagosian, KYC a name, GUAR, CAL, FX, WIRE, PROV Duveen, HOLD, WATCH, PITCH, and since v27 the ocean’s TIDE sculpture, READ 5m 10y low, FISH Rembrandt, STONE Bouvier, WHISPER Klimt, PLAY export Italy, TEMP London, OCEAN; since v28 the desk’s BRIEF a sentence, CASE Singapore, WALL kandinsky, SOURCE Puck; FUNC lists them. Every view, dossier, deep-linkable drawer, Lab instrument and Reel card has an address; Back and Forward walk the views and dossiers, and close the Reel onto the page it covered.

The page opens on the World — the globe, turning — with the menu above it (v29.1); the menu (v29) shows eight headliners — Today, the Eye, the School, Ask, the Hammer, the Navigator, the Walls, the Tides — and groups the rest under More (the market · money and law · the library · the company); Compare and Signals are reachable by hash and from Ask but not from the menu.

## Quick start

```
npm install            # jsdom (test), axe-core and Playwright (runtime audit); Python 3 needs no packages for the build
npm run check          # build → test → lint → globals map; the four gates every change must pass
npm run check:full     # the same plus the runtime audit (≈2 min, Chromium) and the Ledger rebuild check
```
The scripts, one by one (`package.json`):

| Script | Runs | What it enforces |
|---|---|---|
| `npm run build` | `python3 build.py` | assembles `build/rostrum.html` (the artifact page) and `build/preview.html` (browser wrapper); counts the collections by evaluating the data in Node; refuses a missing or doubled placeholder, a `</script` in pasted text, a zero count or an unreplaced token |
| `npm test` | `node test.js` | jsdom smoke test over `preview.html`: every view, drawer, dossier, the Reel, deep links, hash restore, search; exits 1 unless the last line is `errors: none` |
| `npm run lint` | `node tools/lint_data.js --quiet` | the data-layer lint: ids, every cross-reference, images, flags, dates, URLs, the engine-facing contracts (`HUBS[].room`, `ARTIST_DIED`, `REGIMES` booleans, `HERO`, `FLOOR`, `NEWS[].dt` …); exits 1 on ERROR |
| `npm run globals` | `python3 tools/globals.py --no-tables` | who declares and who uses every top-level name across the concatenated files; fatal collisions fail |
| `npm run audit` | `node tools/audit_runtime.js` | Playwright + axe-core: errors in four viewport/theme contexts, overflow at 320, 390 and 1400 px, the masthead at 1280–1920 px, 475 deep links, keyboard and focus, accessibility, reduced motion, storage failure, performance; exits 1 on any failure |
| `npm run shots` | `node tools/audit_runtime.js --shots` | desktop and phone screenshots of the main views into `shots/` |
| `npm run ledger:check` | `python3 tools/nga_subset.py --check` | rebuilds `data/nga_subset.json` from the NGA CSVs and `data/nga_ids.txt` and checks it is byte-identical |

To preview locally, open `build/preview.html` in a browser: the pictures resolve from `build/img/`, Google Fonts load if the machine is online, and everything that needs the artifact host (the Salon board, the pipeline store, CSV saving, "Refine with Claude") degrades to a message or a clipboard copy. `test.js`, `audit_runtime.js` and `shots.js` run against `build/preview.html`, so build first. The runtime audit expects Chromium at `/opt/google/chrome/chrome` (override with `CHROME=…`). `tools/nga_subset.py` needs the two NGA CSVs (about 170 MB) in `data/`; `--fetch` downloads them.

The tree is a git repository (`main`; first commit "Subhasta v14 baseline"). It has no remote yet: the artifact's published `src/…` files are the copy a fresh session can reach, so every editing session republishes them (see Publishing).

## Publishing

The page is `build/rostrum.html`, published with the Artifact tool to the existing artifact URL so that the address and the 234 picture files are kept; the whole source tree (sources, tools, docs, audits, data registries) is republished alongside it under `src/…` so that a fresh session can rebuild it. The exact `files` map, the `root`, and the content-type rules (`.py` scripts and `page.html` go as `text/plain`) are in `REFRESH.md` §4, which also keeps a `## Versions` ledger of what each artifact version carries. v22 declared a new full set of capabilities — db rules for `live/`, `kb/` and `gaps/` beside the members' cards and the board, comments for the Circle's invitation, downloads, sample, user profile — and pinned the runtime contract to 0.2.88; every later republish omits `capabilities` so the declaration is carried forward. A second, shareable artifact carries the same page with the owner's own Desk lines made neutral (`python3 build.py --share` writes `build/share.html`); it has its own database.

## The monthly refresh

A scheduled task runs on the 1st of each month (08:52 New York time) in a fresh cloud session; it also folds in what the live desk wrote and republishes the shareable copy. It reads the published source from the artifact (`REFRESH.md` §1), updates `TODAY` and the dated collections (dispatches, calendar, fairs, upcoming lots, news, signals, the hubs and symptoms touched by the month's marquee weeks), rebuilds, tests and republishes (§3–§4). The data map in `REFRESH.md` §2 says which constant holds what; `ARCHITECTURE.md` §7 explains the fields and the order of edits for each kind of addition.

## The live desk (daily)

A second scheduled task, the research desk, runs every morning (06:43 New York time; twice a week until 23 November 2026). It reads the questions readers could not get answered (`gaps/` in each artifact's database), researches them and the week's sales, and writes what it finds into the database: `kb/<id>` entries the analyst cites from then on, and the `live/` documents Today draws (`read`, `sales` with results as the hammer falls, `wire`, `status`). It never republishes the page, changes sharing or capabilities, or creates artifacts; the monthly refresh folds what it wrote into `src/data_live.js` and the dated collections. The formats and the checks a document must pass (`liveValid`, `kbValid` in `src/today.js`) are in `REFRESH.md` §5.
