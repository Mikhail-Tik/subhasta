## 1. Shape of the system

Subhasta is one HTML document. `build.py` pastes a stylesheet (four files), thirteen data files, a JSON array of 771 provenance records, one application IIFE (with eight engines pasted inside it) and one Reel IIFE into the slots of `src/page.html`. The result is published as a Claude artifact; the artifact also carries 117 pictures (full size and thumbnail) and, under `src/`, the whole repository tree except its outputs and inputs that can be refetched (§6), so a fresh session can rebuild, lint, test and republish without this machine. Locally the tree is a git repository (`main`, no remote).

Three layers, three scopes:

| Layer | Files | Scope in the built page |
|---|---|---|
| Data | `src/data_houses.js`, `data_market.js`, `data_more.js`, `data_people.js`, `data_reel.js`, `data_under.js`, `data_pulse.js`, `data_atlas.js`, `data_world.js`, `data_flows.js`, `data_globe.js`, `data_circle.js`, `data_bench.js`; `const NGA` (injected JSON) | **page**: plain script-level `const` globals, visible to every script |
| Application | `src/app.js` with `under.js`, `pulse.js`, `atlas.js`, `clinic.js`, `globe.js`, `circle.js`, `lab.js`, `lab_prov.js`, `lab_hands.js` pasted at its placeholders | **app**: one IIFE block scope shared by the ten files |
| Reel | `src/reel.js` | **reel**: its own IIFE; reaches the app only through `window.__S`, exposes `window.__REEL` |

There is no module system: a name declared at the top of any data file is a global; a name declared at the top of `app.js` or of a pasted engine is visible to all nine app files and to nothing else. `tools/globals.py` maps the result (371 top-level declarations, 0 fatal collisions, five cross-IIFE name duplicates: `$`, `$$`, `esc`, which the Reel's header declares as deliberate copies, and `perf`, `show`, two unrelated functions of the same name).

Rendering is string templating: every view and dossier builds an HTML string with template literals (`esc()` on all data), assigns it to `innerHTML`, then binds behaviour by `data-*` attributes (`bindLinks`, `bindTips`, `bindLightbox`, `bindUnderLinks`, `bindAtlasLinks`, `bindLensButtons`, `bindCopies`, `bindWatch`). Charts are hand-built inline SVG strings (`groupedBars`, `hbars`, `spark`, `treemap`/`squarify`, `pricePath`, `sankeySVG`, `ringSVG`, `lineArea`, `stackedShares`, `worldSVG`, `miniWorld`); every focusable chart mark carries the tooltip text as `aria-label` (`tipText`). No library is loaded at runtime; the only external resources are the Google Fonts stylesheet in `page.html` and the same-artifact `img/` files.

## 2. Build pipeline

`python3 build.py` (standard library, plus Node for the counts) assembles `src/page.html` by `str.replace` and refuses to write when anything is off. Since October 2026 the data order ends with four more files — `data_flows.js`, `data_globe.js`, `data_circle.js`, `data_bench.js` (placeholders `/*__DATA_FLOWS__*/`, `/*__DATA_GLOBE__*/`, `/*__DATA_CIRCLE__*/`, `/*__DATA_BENCH__*/` after `/*__DATA_WORLD__*/`) — app.js carries four more engine placeholders after `/*__CLINIC__*/` (`/*__GLOBE__*/` ← `src/globe.js`, `/*__CIRCLE__*/` ← `src/circle.js`, `/*__LAB__*/` ← `src/lab.js`, `/*__LABPROV__*/` ← `src/lab_prov.js`, `/*__LABHANDS__*/` ← `src/lab_hands.js`), and `style.css` is followed by `globe.css`, `circle.css` and `lab.css` inside the same `<style>`; §9 and §10 describe these layers. Facts worth knowing about the build:

- **Order of evaluation in the page** is the order of the `<script>` body: the thirteen data files (houses → market → more → people → reel → under → pulse → atlas → world → flows → globe → circle → bench), then `const NGA`, then the app IIFE, then the Reel IIFE. A data file may reference a constant from an earlier data file at top level; anything later is a forward reference that only works inside a function body. `data_pulse.js` does this legitimately (`PS` closes over `PULSE_SRC` in the same file); no data file references another at top level today. The order is stated in a comment at the top of the `<script>` in `page.html` and, for the engines, in the comment block above the four placeholders in `app.js` (what an engine may use at load, and why `RENDER` and `window.__S` must stay below them).
- **Placeholders** are exact strings: `/*__CSS__*/`, `/*__DATA_HOUSES__*/` … `/*__DATA_WORLD__*/`, `/*__NGA__*/[]` (the `[]` is part of the placeholder, so the unbuilt template is itself valid JavaScript), `/*__APP__*/`, `/*__REEL__*/` in `page.html`; `/*__UNDER__*/`, `/*__PULSE__*/`, `/*__ATLAS__*/`, `/*__CLINIC__*/` in `app.js` (lines 449–452, after the Lexicon and before the palette); `/*__IMGMETA__*/{}` in `data_reel.js` line 2. The build asserts that each occurs exactly once in its file (a missing or doubled placeholder stops it) and, after assembling, that no `/*__X__*/` or `${…COUNT}` token is left in the output. The replacement itself is global, so a placeholder string occurring inside a data string would still be replaced.
- **Counts.** `${ALLCOUNT}` (HOUSES + PLAYERS), `${PEOPLECOUNT}`, `${LOTCOUNT}` (RESULTS + RESULTS_MORE), `${UNDERCOUNT}` (ATLAS), `${HUBCOUNT}`, `${SEGCOUNT}`, `${INSTCOUNT}` (INSTITUTIONS) come from evaluating the nine data files in a Node `vm` sandbox exactly as the lint does (`const` → `var`, the IMG JSON injected) and reading `.length`; `${NGACOUNT}` is `len(nga)`. The tokens appear in the colophon (`page.html`) and in the Reel's closing card (`data_reel.js`, kind `cta`) and are substituted over the whole assembled output last. If Node is missing or the evaluation throws, the build prints `warning: counting with regexes (…)` on stderr and falls back to the old regexes over the source text (`\n\{id:'`, `\n\{artist:'`, `\n\{n:'`, and `split()` anchors such as `const HUBS=` … `const COUNTRY_SHARE`); a count of zero in either mode stops the build. The summary line says which mode was used (`counted by node` / `regex`). Note that a data file that fails to evaluate is therefore not a build error by itself: the page is still written and `test.js` or the lint reports the breakage.
- **Escaping.** The NGA JSON and the IMG JSON have `</` escaped to `<\/`. Everything else is pasted verbatim, so the build scans every piece (stylesheet, each data file, the assembled app, the Reel, both JSONs) for `</script` case-insensitively and refuses if it finds one.
- `build/preview.html` wraps the same bytes in a document skeleton (doctype, `<html lang="en">`, viewport, a tiny reset); the artifact host supplies its own skeleton for `rostrum.html`. The preview is what `test.js`, `tools/audit_runtime.js` and `tools/shots.js` load over `file://`.
- Output size: 1.6 MB; roughly 116 KB is `data_world.js` path strings and about 728 KB the NGA JSON. There is no minification.

## 3. Runtime

### 3.1 Boot sequence (`start()`, app.js 496–498)

`start` runs at the end of the app IIFE (immediately if the document has parsed, else on `DOMContentLoaded`; the `<script>` sits after the markup, so in practice immediately). Before `start`, the IIFE body has already run its top-level statements: helpers (`esc`, `slug`, `norm`, `words`, `fdate`, `fspan`, `mm`, `bn`, `store`…), the capture-phase `error` listener for broken images (line 27), the data assembly at lines 34–52 (`RESULTS.push(...RESULTS_MORE)`, `PRIVATE_TREATY.push(...PRIVATE_MORE)`, `STORIES.unshift(...STORIES_MORE)`; `PEOPLE[i].id = 'p'+i+'-'+slug(name)`; `RESULTS[].id = slug(surname-title)` and `.chain` from `CHAINS[title]` or a matching `PROV_CASES` entry; `BYPRICE` ranks; `ALL` = HOUSES tagged `kind:'house'` + PLAYERS tagged `kind:'player'`; `NGA_ARTISTS`, `ARTISTS`), the engines' own top-level constants (`FLOW`, `PRESETS`, `LENS` read from storage, `REGION_BOX`, `LABEL_OFF`, `CLINIC_FLAGS`, `STRICT_EXPORT`/`NO_AML` derived from `REGIMES`…), `const RENDER` and `window.__S`.

Then, in order:

1. `fixShell()` — sets `lang="en"` on `<html>` if the host's skeleton did not. That is all it does now: `page.html` itself carries the `<div id="drawer" role="dialog" inert>`, the `title`d masthead chips and the menu button's `aria-controls`/`aria-expanded`.
2. `initTheme()` — applies `store.get('theme')` as `data-theme` on `<html>`; wires `#themeBtn` (toggles between the current or system scheme and its opposite, persists).
3. `initPalette()` — `buildIndex()` builds the palette index once (sections, organisations, lots, artists, people, upcoming, collectors, stories, terms, dealers, signals, dates, undercurrents, stations, symptoms, vitals, hubs, segments, fairs, institutions, reports) and precomputes each entry's normalised search text; binds the input, arrow keys, Enter.
4. `initNav()` — nav buttons (`data-v="reel"` opens the Reel over the page on screen through `openReelHere`, the Floor only when nothing is shown yet; every other value calls `go()`), home button, menu button (`aria-expanded`), lightbox click-to-close, Tab traps on drawer/palette/lightbox, the global `keydown` (Ctrl/⌘-K opens the palette at any time; Escape closes the lightbox, else defers to the Reel if it is open, else closes the palette, else the drawer; with the Reel closed and no input focused, digits 1–9 switch to `VIEWS[n-1]` (Floor to Salon) unless a modifier is held, and `/` opens the palette), and `hashchange → route`.
5. Drawer close and scrim click → `closeDrawer`.
6. `renderView('desk')` and `renderView('salon')` are forced before routing, because `initCaps()` will draw the pipeline, the board and the members into their DOM.
7. `route()` — renders and shows whatever the hash asks for (§3.2).
8. `booted = true` — from here `show()`/`detail()` move focus to the view heading when nothing sensible has focus.
9. `initCaps()` — asynchronous; requests the four host capabilities in parallel and subscribes to the database (§3.12).
10. A debounced `resize` listener redraws the treemap (Floor only) and re-measures scrollable regions.

### 3.2 Routing (`route()`, `onAddress()`, `setHash()` in app.js)

The hash is the only URL state, and since v21 it keeps a history. `route()` runs at boot and through `onAddress()` on every `hashchange` and `popstate`, once per change (`lastHash` is the address last handled, so a browser that reports both events routes once). Internal navigation writes the hash with `setHash(h, push)`: a view (`go`) and a dossier (`detail`) push an entry once the app has booted and while no address is being routed (`booted`, `routing`), so Back and Forward walk the reader's path; drawers, the station ring and an address that is already current replace the entry. Neither fires `hashchange`, so the router never re-enters itself. `setHash` returns whether it pushed: only then does `detail()` relabel the dossier's back button with the place it came from (`placeName`: a view's nav name, Signals capitalised, a drawer's view, a dossier's kind) and send it through `history.back()`, so the button and the browser agree; otherwise the button keeps its `data-go`. `restoreAddress(h)` puts an earlier address back without a new entry (with no address to restore, the Floor replaces the Reel's). `pageHash` is the address whose page is on screen, set by `setHash` and by the Reel branch when it shows the Floor; when the Reel closes back through history it names its destination first (`__S.returning`), and `onAddress` skips routing when that page is still on screen, so a dossier keeps its back button and the Lab its scroll. Grammar, in the order `route()` tests it:

| Hash | Handled by | Result |
|---|---|---|
| *(empty)*, `#reel`, `#reel-N` | `window.__REEL.open(i)`; the Floor is rendered and shown underneath only when no view is on | the Reel open on card N (1-based) over the page on screen. An entry the browser made for a link or a typed address (no state) is marked `{reel:1, from:<the address before>}` first, so Close returns there (§3.7). N is clamped to 1…`REEL.length` before the call, so `#reel-0` opens the first card and `#reel-999` the last; the Reel then rewrites the hash to the card it shows |
| `#floor` `#pulse` `#atlas` `#houses` `#people` `#hammer` `#signals` `#ledger` `#salon` `#undertow` `#desk` `#lab` `#lexicon` `#circle` | `go(v)` | the view (lazy render, §3.3) |
| `#lab-<instrument>`, `#lab-limits-<area>` | `go('lab')`, `setHash` (kept), scroll and focus | the Lab at that instrument (`LAB_INSTR` ids) or at that area of the limits register (`LIMIT_AREAS` keys) |
| `#inst-<id>` | `go('atlas')`, `openInstitution(id)` | Atlas with the institution drawer |
| `#symptom-<id>` | `go('pulse')`, `openSymptom(id)` | Pulse with the diagnosis drawer |
| `#hub-<id>` | `go('atlas')`, `openHub(id)` | Atlas with the hub drawer |
| `#segment-<id>` | `go('atlas')`, `openSegment(id)` | Atlas with the segment drawer |
| `#under-<id>` | `go('undertow')`, `openAtlas(id)` | Undertow with the undercurrent drawer |
| `#station-<id>` | `go('undertow')`, `selectStation(id,true)`, `setHash` | Undertow with the ring turned to the station |
| `#person-p<i>-<slug>` | `openPerson(id)` | dossier page |
| `#house-<id>` | `openOrg(id)` → `openHouse` or `openPlayer` (`byId` searches HOUSES ∪ PLAYERS) | dossier page |
| `#lot-<slug>` | `openLot(lotById(slug))`, slug = `slug(surname + '-' + title)` | dossier page |
| `#artist-<slug>` | `openArtist(artistBySlug(slug))`, from `ARTISTS` = NGA artists ∪ RESULTS artists | dossier page |
| `#collector-<id>` | `openCollector(id)` | dossier page |
| `#story-<id>` | `openStory(id)` | dossier page |
| anything else, or an id that does not resolve | `go('floor')` | Floor, hash rewritten to `#floor` |

`slug()` (app.js 11) lowercases, strips `’'".,:()`, turns every other non-alphanumeric run into `-` and trims; `LINKS(artist, slug)` in `data_more.js` receives it so the Artnet URL and the deep link agree. The dossier routes do not call `go()`, so `current` keeps its previous value and the masthead shows no active section while a dossier is open; the dossier's back button (`back(v,label)`) calls `go(v)`.

Hash writers: `go` (view, pushed), `detail(html, hash)` (dossiers, pushed; it also keeps the hash in `detailHash`), `openAtlas`/`openSymptom`/`openHub`/`openSegment`/`openInstitution` (drawers that are deep-linkable, replaced), the station and Lab branches of `route` (replaced), and the Reel's `setAddr()` (`#reel-N`, §3.7), which reports each address to the app through `__S.noteHash` so `lastHash` stays true. Drawers for upcoming lots, evidence, provenance records, vital signs and the lens set no hash and have no deep link. `closeDrawer` gives the address back: if the hash is one of the five drawer kinds it writes `detailHash` when a dossier is open underneath, else `current` (`test.js` asserts both cases).

### 3.3 Views: registry and lazy rendering

- `VIEWS` (app.js 85) is the ordered list of twelve view ids; the order is also the 1–9 hotkey order and the order of the palette's "Section" entries, whose display names live in a parallel array in `buildIndex()` (line 456) that must be kept aligned by hand (the palette shows a hotkey only for the first nine).
- `RENDER` (line 490) maps each id to its renderer: `renderFloor`, `renderPulse` (pulse.js), `renderAtlas` (atlas.js), `renderHouses`, `renderPeople`, `renderHammer`, `renderSignals`, `renderLedger`, `renderSalon`, `renderUndertow` (under.js), `renderDesk`, `renderLexicon`.
- Each view owns a `<section class="view" id="v-<id>">` in `page.html`, plus `#v-detail` for dossiers. `show(v)` toggles `.on`, closes the drawer, runs `firstVisit()`, syncs the nav, scrolls to top, marks scrollable regions, settles focus.
- `rendered[v]` (line 86) makes rendering lazy and one-shot: `go()` calls `renderView(v)` only the first time. `renderView` isolates each renderer in try/catch (a failing view shows a one-paragraph notice and logs; other views are unaffected), then runs the three cross-cutting binders (`bindAtlasLinks`, `bindUnderLinks`, `bindLensButtons`) on the section, and records the first render time in `perf[v]` (exposed as `window.__S.perf`).
- After the first render a view is never re-rendered. Interactive parts redraw themselves with module-level state objects and draw functions: Houses `hstate`/`drawDir`; People `pstate`/`drawPeople`; Hammer `rstate`/`drawHammer`; Ledger `lstate`/`drawLedger`; Undertow `FLOW`/`drawFlow`, `stationSel`/`selectStation`, `atlasFilter`+`atlasQ`/`drawAtlas`, `drawChecks`; Pulse `eraSel`/`drawLongview`; Atlas `atlasRegion`/`drawHubs`, `segGroup`/`drawSegments`; Desk `pipeline`/`drawPipeline`, `watchlist`/`drawWatching`; Salon `posts`/`drawPosts`, `members`/`drawMembers`. The lens apply (`openLens`) re-renders every `.lens` bar and `.foryou` block in place, in whichever views exist.
- **Free-text search** (directory, people, hammer, ledger, palette) normalises both sides with `norm()` (app.js 13: lower case, `’` → `'`, diacritics stripped), so `sotheby's` finds Sotheby’s and `cezanne` finds Cézanne. The Undertow atlas filter and the glossary filter still compare plain `toLowerCase()`.
- **Editorial copy that moved into the data**: the Floor hero (`HERO`), the "Figures verified …" chip (`MARKET.verified`), the third and fourth KPI tiles (`evTile()` over `EVIDENCE.bigthree`/`.private`), the Floor teaser strips (`FLOOR.vitals`, `FLOOR.under`), the wire's and the dispatches' date ranges (from `NEWS[].dt`, `DISPATCHES[].d`), the ECG label (`SERIES.global`), the fairs range (`FAIRS`), and the counts "all eleven" signals, "thirty-six artists", "thirty-one hubs / twenty-four segments / twenty-nine institutions" (`words(X.length)`). **What is still literal in the engines**: the KPI labels and chart subtitles ("Global art market, 2025", "2019–2025", "2025 sales by country"), the Hammer period filter, "2026 schedule" (lot page, Lexicon), "all four major houses raised it in 2026", "Leadership, 2026", the Signals framing ("in 2026", "to June 2027", "tested 1 October 2026"), the Pulse chart notes and "sixteen readings, 2025 to October 2026", "sixteen diagnoses", "The long view, 1744–2026" and its era chips, "Verified against the 2026 reports", "Museums, 2025", the Atlas "2025 share" and its year-ahead line on 2027 dates, "twenty-four corners", the Undertow "sixteen stations", "Ten checks", the Ledger's "81,540 objects" (twice), the Clinic year input `max="2026"`, the Reel's "Art Basel & UBS Global Art Market Report 2026" and its "2025" watermark, and the spelled-out "sixteen vital signs" on the Floor. REFRESH.md §3 step 1b is the list to re-read at every refresh.

### 3.4 Dossier pages and drawers

Two presentation modes share one convention: a **dossier** replaces the main area; a **drawer** slides over the current view.

- `detail(html, hash)` (line 108): closes the drawer, writes `#v-detail`, shows it, clears the nav highlight, scrolls to top, records `detailHash` and sets the hash, binds copies/tips/links/lightbox, marks scrollables, settles focus. Used by `openHouse`, `openPlayer`, `openPerson`, `openLot`, `openArtist`, `openStory`, `openCollector`. Dossiers carry `back(view,label)` and, where it makes sense, `watchBtn('kind:id')` (★ Watch) and an "Add to Desk" button that calls `addToPipeline`.
- `openDrawer(title, sub, bodyHtml)` (line 116): remembers the opener for focus return, fills `#dTitle`/`#dSub`/`#dBody`, clears the drawer's `inert`, makes the page behind `inert`, binds copies/links/lightbox, focuses the close button. `closeDrawer` (line 117) reverses it, restores the hash (§3.2) and returns focus. Used by `openUpcoming`, `openEvidence`, `openProv`, `openAtlas`, `openVital`, `openSymptom`, `openLens`, `openHub`, `openSegment`, `openInstitution`. Links inside a drawer that open a dossier or another view close the drawer first (`detail()` and `show()` both call `closeDrawer`).
- Drawer bodies that are deep-linkable include a "Copy link" button whose value is `location.href.split('#')[0] + '#<kind>-<id>'`.

Every binder has a per-element guard (`__b`, `__u`, `__f`, `__a`, `__l`, `__lb`, `__k`, `__t`) so calling binders repeatedly on overlapping roots is safe; `bindCopies` has no guard and relies on being called once per freshly rendered fragment.

### 3.6 The palette

`buildIndex()` runs once at boot and produces `palIdx`: `{k (kind label), n (name), sub, v (right-hand value), f (action), s (normalised `n + sub + k`)}` for about 820 entries spanning every collection. `palSearch(q)` is a substring match of `norm(q)` over `s`, first 14 hits (or the first 8 entries when empty); `palPick` closes the palette and runs `f`. `#palres` is a `role="listbox"` of `role="option"` rows and the input's `aria-activedescendant` follows the highlighted row (`palMark`). Actions compose the public openers (`go`, `openOrg`, `openLot`, …) and, for Ledger dealers, click the dealer row after `go('ledger')`. Because the index is static, data added at runtime (board posts, pipeline rows) is not searchable, by design.

### 3.7 The Reel (`src/reel.js`)

A separate IIFE so that its helpers and timers cannot collide with the app's, pasted after the app so `window.__S` exists when it evaluates (`const R = window.__S` at line 13).

- **Bridge, app → Reel** (`window.__S`, at the end of app.js), 48 members. The Reel reads the openers `go, openLot, openAtlas, openSymptom, openHub, openSegment, openStory, openUpcoming, openEvidence`; the lookups `lotById, lotByTitle, houseName, flowModel, FLOW, premium, SCHED, pricePathSVG(r,tall), miniWorld(hubId), copy(text)`; the formats `mm, fdate, fspan, fmtUSD`; the data `ATLAS, SYMPTOMS, HUBS, SEGMENTS, SEGGROUPS, CALENDAR, SIGNALS, EVIDENCE, UPCOMING, STORIES, PRIVATE_TREATY, TODAY, NOW`; and the address hooks `restore(h)` (`restoreAddress`), `noteHash(h)` and `isBooted()`. The rest are hooks for `test.js` and the audit: `perf`, `labpRead`, `labhRead`, `labhHolder`, `dealerMatch`, `arrApplies`, `initFlow`, `dispName`, `impliedHammer`. The header comment of reel.js (lines 6–12) lists exactly this set and must be kept in step with app.js by hand. The Reel also reads six page globals directly: `IMG`, `LOTIMG`, `UPIMG`, `REEL`, `CREDIT`, `JOURNEYS`.
- **Bridge, Reel → app** (`window.__REEL`): `open(at)`, `close()`, `isOpen()`, `perf` (`build`, `firstCard` ms). The app calls `open` from the nav, the Floor and Salon buttons, the first-visit guide and `route()`; `go()` and `route()` call `close()` when navigating away; `initNav` consults `isOpen()` to suppress hotkeys and Escape while the Reel is up.
- **Cards**: `REEL` (data_reel.js) is an ordered list of 40 `{k, ref, i?, kick, big?, sub?}`. `card(c,i)` renders by kind, resolving `ref` through the bridge (lot/path → title; up → UPCOMING title; story → id; signal → SIGNALS title; treaty → work; kpi → EVIDENCE key; under → ATLAS id; journey → JOURNEYS id; symptom → SYMPTOMS id; hub → HUBS id; segment → SEGMENTS id; fees/cal/money/cta need no ref) and falls back to the item's own image when `i` is absent (it writes `c.i` and `c.pre` back onto the REEL entry). The `signal` card's button reads `All ${R.SIGNALS.length} signals`; the `cta` card's nav list is a literal of ten views (no Signals, no Lexicon). `safeCard` wraps each card so a broken reference becomes a placeholder card and later `#reel-N` links keep their positions. `build()` runs once, on first open.
- **Timing and input**: `DUR` per kind (16 kinds, 8–12 s); `tick()` drives the progress bar with `requestAnimationFrame` and advances; `prefers-reduced-motion` disables auto-advance, count-ups and the price-path draw; hold to pause, click left/right third, wheel, vertical swipe, arrow keys, `p` to pause. Space advances, also on the Close button where focus lands when the Reel opens, and presses any other focused control. Every opening starts the Reel playing; a hidden tab pauses only an open Reel; a paused Reel stays paused from card to card. `show(i)` wraps modulo (so Previous on the first card goes to the last), writes `#reel-N` through `setAddr`, preloads the next two images and sets the blurred backdrop; the clamp for incoming links lives in `route()`, not here. An upcoming lot whose sale date is before `NOW` gets the kicker “Offered · house · date · the result comes with the refresh”.
- **History**: every Reel entry carries `history.state.reel`. Opened from a page of this session by a button (`openReelHere`: the nav, the Floor, the Salon, the guide, the palette), the Reel pushes one entry `#reel-N` with `{reel:1, from:<the page's hash>}`; opened by a link or a typed `#reel-N`, the browser's own entry is marked the same way by `route()`. Later cards replace the entry. Close and Escape go back through history (`goBack`), so the browser's Back closes the Reel too and both land on the page it covered, which stays shown behind it and is not routed again. Back onto a Reel entry later reopens it with the same way out. Landed on directly (`#reel-N`, or no hash), the entry is `{reel:1, from:null}`, and closing it replaces the address with `#floor`, so Back leaves the page rather than reopening the Reel. A card that opens a drawer (an upcoming lot, the evidence) goes back first and opens the drawer over the page; a dossier opened from a card pushes over the Reel's entry and keeps its default back button. Ctrl-K does nothing while the Reel is open; the palette lists the Reel as a section.
- **Focus**: `openReel` remembers the opener and makes `.mast,.shell` inert; `closeReel` restores (keeping inert if a drawer is open) and returns focus.

### 3.8 The lens (`src/pulse.js` 1–20)

`LENS = {role, region}` with defaults `collector`/`na`, merged with `store.get('lens')`. `LENS_ROLES` and `LENS_REGIONS` (data_atlas.js) supply the vocabulary; each region names its hubs, its regime (`REGIMES.j`), its segments and its cities. The lens changes two things, and its copy says so: (1) the "For your desk" block (`forYou()`), rendered on the Floor and the Pulse (the Atlas shows the lens bar only): *Your room* (the region's first three hubs), *Your rules* (the regime's import/resale/AML/export lines), *Your corners* (the region's segments), *Your dates* (the next four CALENDAR+FAIRS entries in the region's cities) and *Your angle* (a role-specific line and buttons; the collector's "Follow the money here" button calls `flowForHub` on the first hub); (2) the default sale room of Follow the money: `lensRoom()` maps the region's first hub to `HUBS[].room` and that venue's `homeDest`, and `presetFlowFromLens()` writes them into `FLOW` when `renderUndertow` first runs and again when the lens is applied — but only while `FLOW.touched` is false, i.e. until the reader moves a control, picks a preset, opens a lot's flow or a hub's room. `openLens` is a drawer; applying it stores the lens, re-renders every `.lens` and `.foryou` fragment in place, re-presets the flow if untouched, and toasts. Nothing else reads `LENS`: the Signals and Atlas calendars and the Desk drafts are lens-independent.

### 3.9 Follow the money (`flowModel`, under.js 20–32)

Input `p` is the mutable `FLOW` object: `hammer` (USD), `house` (SCHED key, else Sotheby's), `venue` (VENUES key: ny, london, paris, hk, geneva), `imported` († lot), `structure` (none | house | third), `guar` (guarantee as a fraction of hammer), `feeShare` (guarantor's share of the overage), `seller` ('5' | '10' | '0' | '105' | '109'), `dest` (DESTS key: nyc, londonhome, parishome, hkhome, genevahome, freeport, delaware, museum), `living` (the resale-right box), `artist` (the lot's artist when the flow came from a lot, else `null`), `ship`, `ins` (rate), `loan` (none | bank 3% | spec 9%), and `touched` (set by `readFlow`, the presets, `flowForLot` and `flowForHub`; read by the lens, §3.8).

Steps: premium from the house's marginal schedule (`premium`, app.js 304) → price = hammer + premium → `exported` when the destination is in another country than the room or is in bond (`DESTS.bonded`, the Geneva freeport): the room's VAT is then zero-rated or refunded against proof of export (ATLAS `exportvat`, from the houses' own guides) → VAT on the premium (`VENUES.vatPrem`) and import VAT on the hammer (`VENUES.impVat`, imported lots only), both nil when exported → New York sales tax (venue ny and dest nyc) or New York use tax (dest nyc, bought elsewhere) → the destination's import VAT on the price (`DESTS.impVat`, charged unless `VENUES.country === DESTS.country`: `londonhome` 5%, `parishome` 5.5%, `genevahome` 8.1%) → resale royalty: on when the room has the right and, for a lot's artist, `arrApplies(artist, year, venue)` holds (in term: living, or dead within 70 years by `ARTIST_DIED`; a qualifying nationality: `ARTIST_NATION[artist]` in `ARR_NATIONS`, the UK, the EEA, Australia and New Zealand, an artist missing from the map being assumed to qualify), else when the box is ticked; nothing below the room's threshold (`VENUES.arrMin`: £1,000, €750); `arrAmount()` on the hammer in local currency (FX map inside the function: gbp/eur/chf/hkd from `FX`), tiered 4%→0.25%, capped at `VENUES.arrCap`, and split by `VENUES.arrPayer` into `arrBuyer`/`arrSeller` (the buyer in London and in Paris at auction) → seller's commission or enhanced-hammer bonus → guarantee `G` and the guarantor's fee on the overage (third-party only) → shipping, insurance (`ins × price`; nil where `DESTS.insured`, the museum loan), storage (`DESTS.storage`), loan interest (50% of price at the chosen rate), US estate tax (40% of the whole price: the marginal rate on an estate already above the exemption) and the resale break-even (buyer's all-in ÷ 0.95). The Sankey's nodes are sums of its links, the premium allocated to the guarantor's bonus and fee before the house (`flowSubsidy(m)` is what the house pays from its own pocket when fee and bonus exceed premium and commission, and the note under the diagram says so).

Output: `{H, prem, price, vatPrem, impVat, salesTax, useTax, destVat, arr, arrOn, arrBuyer, arrSeller, commission, bonus, G, fee, ship, taxes, buyer, seller, house, ins, storage, loanP, loanR, interest, estate, breakEven, V, D, sched, exported, imported}`. Consumers: `drawFlow` (Sankey, four KPIs, the 16-line ledger with a `data-under` source button per line — a row's atlas id may be a ternary of literals, which the lint reads — and the destination's rate and name printed from `D`, the five-room comparison), `flowDestinations()` (the same purchase in every destination: VAT in the room, tax on arrival, storage, the first year in all; a destination marked `defer` is shown but never called the cheapest), `flowMatrix()` (every room against every destination, the first year in all against the cheapest: ties within a dollar outlined, the route on screen underlined, `defer` columns shown but kept out of the minimum, the shading and the ranking; the reading names the cheapest route with `DESTS[].act` and the columns use `DESTS[].s`), `flowForLot(r)` (presets from a lot: implied hammer by bisection of `premium`, venue from `venueForCity(r.city)` through `VENUES[].cities` with New York as the fallback, `dest` = that venue's `homeDest`, `living` from `arrApplies(artist, saleYear)` over `ARTIST_DIED`: `null` = living, a year = died then and the right runs 70 years, `false` = not an artist's work), `flowForHub(hubId)` (pulse.js 20: `HUBS[].room` → venue, that venue's `homeDest`, New York when the hub has no valid room), `presetFlowFromLens()` (§3.8) and the Reel's `money` card ($100m at Sotheby's New York, computed through `__S.flowModel`). `PRESETS` (under.js 13–18) are four worked examples, each in its room's money (the London Klimt is a £74m hammer converted at `FX.gbp`); `initFlow()` rebuilds the controls and redraws after a preset, a lot, a hub or the lens changes `FLOW`. The hammer slider is logarithmic from $100k to $2bn (`FLOW_SL`, `flowSlPos`/`flowSlHammer`, ticks at $100k, $1m, $10m, $100m and $1bn), and `readFlow(src)` reads the hammer only when the slider itself moved, so a preset's hammer or a Lab round trip's $50k survives any other control; the guarantee is clamped to 40–100% (default 85) and the guarantor's fee to 0–50% (default 20). `flowSensitivity()` holds a third-party guarantee fixed in dollars, so in the −20% and −10% columns the guarantor buys at the irrevocable bid, with its own fee row. The five-room comparison tags every room within a dollar of the cheapest, as “tied cheapest” when there are several.

### 3.10 The Clinic (`src/clinic.js`)

Rendered inside the Desk (`clinicHTML`, `initClinic`). `diagnose()` reads artist, year, asking price, channel (auction | private | primary | direct), seller of record (person | company | estate | institution | principal | unknown), sale and destination jurisdictions (every `REGIMES` row), and twelve checkbox flags (`CLINIC_FLAGS`, each tied to an ATLAS id). `STRICT_EXPORT` and `NO_AML` are built at load from the data: `REGIMES.filter(r => r.strictExport === true)` and `REGIMES.filter(r => r.dealerAml === false)` (today uk, fr, de, it, cn, in, br, mx, pe, au and us, hk, cn, jp, kr, sg, ae, sa). Six risks start at 10 and add fixed increments, capped at 100 (`cap`): *Title and provenance* (+45 1933–45 gap, +50 undocumented antiquity, +15 freeport, +15 company seller, +15 undisclosed seller, +15 resale restriction, +15 possible lien, +5 European 1500–1945 work), *Authenticity* (+30 no catalogue raisonné/board, +20 pre-1800, +10 outside the auction room, +15 Chinese 20th-century segment), *Price and liquidity* (+25 price doubled, comparables in RESULTS: 0 / +10 / +20 by count, +15 ultra-contemporary, +10 private channel, +10 urgency, +5 guarantee), *Tax and border* (+15 destination import VAT, +20 strict-export jurisdiction and pre-1976 work, +25 CITES, +10 no dealer AML in the sale jurisdiction, +5 resale right at destination), *Counterparty and payment* (+60 payment to an intermediary's account, +20 dealer as principal, +10 agent-or-principal unknown, +15 deadline in hours, +10 undisclosed seller, +5 lien), *Condition* (+30 no condition report, +15 CITES, +10 pre-1900, +15 photographs/prints). Each increment pushes a note with an optional ATLAS id ("why"). Verdict: **Stop** if the worst risk ≥ 70; **Pause** if the mean ≥ 35 or the worst ≥ 50; otherwise **Proceed with the standard checks**. `segmentGuess(year, artist)` picks a SEGMENTS id from whole-name lists (`CL_SEGNAMES`) and year bands, and only when the year allows it (Simone Martini is not post-war, Zhang Daqian is Chinese 20th century); a Segment select (`#clSeg`) overrides the guess. `clinicArtist()` resolves a surname to the artist the data knows ("Bacon" → Francis Bacon) and the meta line says so; a blank year is read as undated, never as 0. Export is tested only when the work leaves the sale jurisdiction (destination ≠ sale), against that regime's own age threshold, with a note that value thresholds also apply; the resale right follows the sale jurisdiction through `arrInTerm`/`arrQualifies` (Bacon sold in London pays, Warhol nowhere). The notes end with a link to the limits register's Clinic area: the scores are increments chosen by the editor, not probabilities. Comparables are the artist's lots in RESULTS; the text version is copyable (the one `onclick` property in the code base).

### 3.12 Storage and capabilities

**Browser storage** goes through `store` (app.js 19): keys are prefixed `subhasta.` and JSON-encoded; every read and write is try/catch-guarded and mirrored in `memStore`, so a throwing or absent `localStorage` keeps the session's own choices alive. Keys in use: `theme`, `seen` (first-visit guide), `bio` (Desk), `lens`, `pipeline` and `watch` (only when the database is unavailable), `under.checks`.

**Host capabilities** are requested in `initCaps()` (app.js 416–426) through `window.claude.use(name)`; without `window.claude` (file://) `finishCaps()` runs at once. The four (`sample`, `downloads`, `db`, `user`) are requested together with `Promise.all`, each wrapped so a rejection or a throw becomes `null`; a host that answers none settles in one timeout (about 10 s), not four, and one refusal does not block the others. `myId` is then read from `user`, the three `onSnapshot` subscriptions are opened, the watch list is fetched, and `finishCaps()` writes the status lines.

## 6. Publish model and the scheduled refresh

**One artifact, three kinds of published file.** The artifact at the URL in `REFRESH.md` holds `index.html` (the page), `img/<id>.jpg` and `img/t/<id>.jpg` for all 117 pictures (234 files, published once and kept across republishes because a publish only adds or replaces the paths it names), and the source tree under `src/`. The map in REFRESH.md §1/§4 publishes the whole repository except what is generated or refetchable: `src/REFRESH.md`, `src/README.md`, `src/ARCHITECTURE.md`, `src/build.py`, `src/test.js`, `src/package.json`, `src/images_manifest.py`, `src/fetch_images.py`, `src/tools/{lint_data.js, audit_runtime.js, globals.py, nga_subset.py, shots.js}`, `src/audit/{data_integrity, runtime_audit, architecture_review}.md`, `src/src/<every file of src/>`, `src/data/{images_meta.json, nga_subset.json, nga_ids.txt}`. Not published: `node_modules/`, `package-lock.json`, `.gitignore`, `build/*.html`, the two NGA CSVs, `data/raw_img/`, `shots/`. **State on 5 October 2026, 23:00:** the live version was still `1791249705-065e` (259 files: the page, the pictures and the pre-v14 snapshot of `src/` — no `tools/`, `audit/`, docs, `package.json` or `nga_ids.txt`; `src/src/app.js` 108 KB against 116 KB locally), so the next publish must send the full map, and until it does the refresh session (below) cannot run the tools and REFRESH.md's ledger entry for v14 describes the intended state, not the published one. The rule in REFRESH.md is that **every session that edits the tree republishes the source map**, page changed or not.

**Local repository.** The tree is a git repository with one commit (`8ae951c`, "Subhasta v14 baseline: sources, tools, docs, pictures", 272 files) and no remote. `.gitignore` excludes `build/*.html`, `build/files_*.json`, `data/raw_img/`, the NGA CSVs, `data/nga_subset_raw.json`, `data/nga_dl.log`, `data/contact*.jpg`, `shots*/`, `__pycache__/`, `node_modules/`, `*.log`; `build/img/` (the 234 published pictures) **is** tracked. Nothing compares the artifact's `src/` with HEAD; REFRESH.md's `## Versions` table is the hand-kept ledger of which artifact version carries which source state, and a refresh session must stop when the page's footer counts or the Floor's verification date disagree with its latest row.

**Content types.** `.js`, `.css`, `.md`, `.json`, `.txt` and `.jpg` are served by extension; `.py` files and `page.html` must be published with an explicit `{"from": …, "contentType": "text/plain"}` or the whole publish is refused (REFRESH.md §4); an HTML file in `files` would otherwise be served as a page of its own.

**Capabilities.** The declaration (§3.12) is stored on the artifact; a republish must omit `capabilities` to carry it forward (an empty object would revoke everything, a partial object would replace the whole set).

**The scheduled refresh** runs on the 1st of each month (from December 2026; the 3rd before) in a fresh cloud session: read the published `src/…` files from the artifact (REFRESH.md §1), reassemble the layout (`src/src/*` → `src/`, `src/data/*` → `data/`, `src/tools/*` → `tools/`, `src/audit/*` → `audit/`, the rest to the root), check the `## Versions` ledger, `npm install`, `npm run check`, edit the dated collections by the rules of §3 (incl. `MARKET.verified`, `HERO`, `FLOOR`, `ARTIST_DIED` for new artists, `room` for new hubs, `strictExport`/`dealerAml` for new jurisdictions, `dt` for new wire items), `npm run check` and `npm run audit` again, publish `build/rostrum.html` to the same URL with `root` = the project and `files` = the same source map so the next run inherits the edits. Because the refresh session only has what is published, anything left out of the `files` map is unavailable to it.

## 7. How to add things

Each list is in the order the edits should be made. Finish every one with `npm run check` (build, test, lint, globals), and `npm run audit` before publishing.

**A new lot (a sold work).**
1. `src/data_more.js` → `RESULTS_MORE` (or `data_market.js` → `RESULTS`): `{artist, title, year, price, house, city, date, cat, rec:[…], note}`; `price` in USD millions with premium; `house` a HOUSES id; `cat` in CATS; `date` ISO and not after `TODAY`. ## 8. Known limitations and risks

- **One 1.6 MB document.** First paint waits for the whole document to parse (first contentful paint about 340 ms on a desktop, longer on phones); the levers are `data_world.js` path precision and the 728 KB NGA JSON. There is no code splitting, no minifier and no source maps; errors in the published page point at line numbers of the concatenated script.
- **Globals and a shared block scope.** Every data constant is a true global; the nine app files share one scope, so a new top-level `const` in `pulse.js` can collide fatally with one in `atlas.js` and only `tools/globals.py` or loading the page will tell. Data files must never touch the DOM (the lint checks) or reference a later file at top level; an engine's top-level statement may use only what app.js declares above the placeholders (the comment there says so).
- **Regex-read engine constants.** The lint's view of `VIEWS`, `SCHED`, `DUR`, the FX map and the engine literals depends on exact source formatting (`const X=[`, `data-under="…"` with a literal id); a reformatting that is valid JavaScript can make a check fall back to its built-in default (the lint prints a NOTE). The build itself evaluates the data, but its regex fallback (Node absent) has the same dependence on `{id:'` at column 0.
- **Content Security Policy of the host.** The artifact host blocks external `fetch` and external images (stated in the project brief; not re-tested here), which is why every figure is inline data and every picture a same-artifact `img/` file; the only cross-origin resource is the Google Fonts stylesheet, and if it fails the stacks fall back to Georgia/Arial/Menlo. Behaviour is attached with `addEventListener` throughout (one `onclick` property in `clinic.js`), never with HTML event attributes.
- **Capabilities are optional.** `initCaps` requests the four together; a host that serves none still takes one timeout (about 10 s) to settle, during which the Salon shows "Loading the board." and the pipeline is empty.
- **Database rules protect the roster and the board.** Each member writes only their own card and their own board document, and the owner can write all, so the owner can remove any post; `data/users/<uid>/…` is private; nothing is encrypted and shared data is untrusted input (every string is passed through `esc()`).
- **Dated prose in the engines** must be refreshed by hand: the list in §3.3 (REFRESH.md §3 step 1b). Counts that are derived (`words(X.length)`) cannot drift; the spelled-out "sixteen", "twenty-four", "ten" and "six" can.
- **Heuristics that look like data.** `segmentGuess`'s name lists; `openCollector`'s match against lot notes and chains (whole words since v21; a record of two people, "Liu Yiqian and Wang Wei", is two names, a family-name-first name matches only whole, and a surname two collectors share needs the first name; a record may list its lots instead, `COLLECTORS[].lots`); `openSegment`'s first-word match against people's remits; `imgsFor`/`ngaFor`'s surname matching for artist pages; `venueForCity`'s New York fallback for Online, Stuttgart, Dallas and Beijing lots; the palette's section names parallel to `VIEWS`. Each is an engine literal that a data edit can silently invalidate.
- **Hash state is partial.** Drawers for upcoming lots, evidence, provenance records, vitals and the lens are not addressable; the deep-linkable drawers hand the hash back on close and replace rather than push, so Back skips them; `#reel-N` is clamped on the way in, but the Reel's own Previous from card 1 wraps to the last card. Closing a Reel that was landed on replaces its address with `#floor`; a Reel address typed while the Reel is already open is treated as a landing.
- **Share links name the page's own address.** "Copy link" buttons and the Reel's share copy `location.href` with a hash. Inside the artifact host that address may be the frame's, not the claude.ai link a reader would share; the claude.ai link plus the hash is the reliable form, and the copy says nothing about who can open it (the artifact is private until its owner shares it).
- **The reader's date and the terminal's.** `TODAY` is the date the data speaks for ("as of"); `NOW` is the later of `TODAY` and the reader's local date and decides what is still upcoming. A lot whose sale date has passed is shown as "offered; the result comes with the refresh" until the next refresh adds the result: the page never invents one.
- **The published source can lag the repository.** The refresh runs from the artifact's `src/…`, so unpublished local edits are invisible to it and would be overwritten by the refresh's own republish; on 5 October the artifact still carried the pre-v14 snapshot (§6). The `## Versions` ledger and the republish-after-every-session rule are the only guard; no tool compares the two.
- **Third-party image sources.** `images_manifest.py` points at files in other people's GitHub repositories; they are needed only to add or regenerate pictures, and the public-domain status rests on the manifest author's check, not on a licence file.
- **Personal defaults.** The Desk's signature and `DEFAULT_BIO` name the owner; the bio is editable in the page, the signature is not.

## 10. The Lab: measures computed from the data (October 2026)

**Files.** `src/lab.js` (engine, pasted at `/*__LAB__*/`), `src/lab_prov.js` (the provenance reading, pasted at `/*__LABPROV__*/` right after it), `src/lab_hands.js` (instrument five, pasted at `/*__LABHANDS__*/` after that), `src/lab.css` (appended after `circle.css`), `src/data_bench.js` (generated: `BENCH`) by `python3 tools/benchmarks.py` (stdlib; S&P 500 total return and price index from Shiller's data extended with FRED, gold from the World Bank series, US CPI-U from BLS, all through the ODC-PDDL `datasets/*` repositories on GitHub; annual averages of monthly values, 1871 to the current year; `meta.through`, `meta.months`, `meta.missing`, `meta.vf` = S, `meta.note`; `src` per series). The view is `#lab` (the twelfth masthead item); `#lab-<instrument>` opens it at `returns`, `roundtrip`, `structure`, `provenance`, `hands` or `confidence` (`route()` scrolls to the section). `LAB_INSTR` names the six for the chips, the palette (`k: 'Instrument'`, built from it with a few search words each) and the Circle's `['lab', instrument]` link kind. Coming back to the Lab redraws the round trip (`go()` calls `labRedraw`), because it reads Follow the money's shipping and imported box. Nothing in the Lab is typed data: every figure is computed at render from the constants, so it moves when the data does.

**1. Returns** (`labPairs()`, `labRetStats()`). A holding period is two consecutive priced points of the same work at least a calendar year apart: `CHAINS` read exactly as `pricePath` reads them (a price for several works, `GROUP_PRICE`, is skipped in both), closed by the published result unless the chain already holds that sale, then `JOURNEYS` steps with a numeric `usd`. Each period gets its nominal CAGR, the real rate (deflated by `BENCH.cpi`), and the S&P 500 total return and gold over the same years (`labB(k, year)`; a year after the series takes its latest value). The figures are the median, the share that beat the S&P 500 and the median margin; the notes name the survivor bias. `labBootMedian()` gives the median a 90% interval from 2,000 resamples of the periods with a fixed seed (mulberry32, seed 1933), so every reader sees the same interval; the reading says it measures sampling noise only, not the survivor bias. Sort state: store key `lab.ret`.

**2. The round trip** (`labRtModel()`). Entry = Follow the money's buyer total for the same inputs (`flowModel`, so the two can never disagree; `test.js` checks it to the dollar); a yearly carry of insurance on the replacement value plus storage (`DESTS[].storage` unless the reader types one); exit hammer = hammer × (1 + g)^T with g defaulting to the median of instrument one; proceeds after the seller's commission and any resale right. Net IRR and the break-even growth rate come from bisection on the yearly cash flows; the waterfall and the comparison with the S&P 500, gold and CPI over the last T years are inline SVG. `labRtScen()` runs the same round trip at each repeat sale's own rate: a dot per period on one axis of net return (`labRtScenSVG`, the loss and the beat in the validated chart pair, the middle in the muted ink; the axis stops at twice the upper quartile or 25%, a dot beyond it sits past the edge with its value). Only periods that began within a factor of ten of the hammer (`LAB_LIKE`) are counted in the reading; the others are hollow rings. The reading says it shows spread, not odds. A destination that insures (`DESTS[].insured`, the museum loan) carries no insurance. The break-even grid (`labRtGrid()`, `LAB_GRID_H` × `LAB_GRID_T`: six hammers from $0.5m to $100m, six holds from one to twenty years) is cached on everything the break-even depends on, including the two settings the round trip takes from Follow the money (`FLOW.imported`, `FLOW.ship`); its reading compares two sizes at the hold on screen and two holds at the hammer on screen, and says why size helps (the house's tiers fall, or the premium is one rate and only the fixed sums weigh less). Inputs persist in store key `lab.rt`.

**3. Structure** (`labStructure()`). Herfindahl–Hirschman index of the big three (`MARKET.bigThree`, by year) and of the countries (`COUNTRY_SHARE`), the top-four share, the price-band split of value against lots, the Gini coefficient and top-ten share of the terminal's own marquee lots, and concentration across named artists: the lots with `ARTIST_DIED[artist] === false` (a watch, a car, a dinosaur) are left out and named by category, the five largest artists' shares are rounded by largest remainder so they add up to the headline (`labRound`), and the bars give value by artist and by decade of sale. An Italian "da" name goes by its first name (`labSurname`: Leonardo, not da Vinci).

**4. Provenance, 1933 to 1945** (`labpRead()`, cached). The 771 NGA histories are read the way the Gallery writes them. The main text is everything before the notes (the last `[1]` after the closing full stop); `tools/nga_subset.py` now never cuts the main text, only the notes (53 records changed in October 2026). Entries split at semicolons outside brackets (a direct transfer) and at full stops between sentences (a break: the link is not known; abbreviations and initials do not split; a footnote marker with no delimiter before a new owner is read as a break). A bracketed lifespan gives a year of death; other bracketed text is set aside. A change of hands is dated by its entry's own year, by the dated sale straight before it, by the death of the owner before an heir, or by an earlier owner's "until"; "by 1927", "in 1908" or "1940–1949" after a name, "as of", "until at least" and "probably until" only bound it, and the Gallery's own entry takes the accession year (the Widener formula, "by gift through power of appointment", is read as that entry when the text never names the Gallery). **Scope**: works made before 1946 (`n.y`) that reached the Gallery after 1932, the American Alliance of Museums' scope, less custody (an institution, a hospital or a church included, that held the work from before 1933 until the Gallery took it). From the owner of 1933 (the last entry acquired or known to be held before 1933; failing that the first holder named) the chain is walked forward: **accounted for** when it stays unbroken to the first change after 1945, or to the Gallery, and every change in between is dated or passes within a family — an inheritance, a gift to a relative, "Mrs. <the owner's name>", the heir at the end of a descent (`state` `held`, `dated` or `family`); a holder documented only "until at least" or "probably until" a year leaves what follows open; otherwise **partly accounted for** when the main text names any year 1933–45, **quiet** when it names none. Each row also carries where the work starts the period (`LABP_PLACES`, countries as they were in 1933, walking back up to three linked entries no older than 1870) and the entry where the chain opens. Output: six figures, a country table and a table of the Ledger's dealers and houses (`DEALERS` through `dealerMatch`, those named in at least five histories in scope, with a base row for the whole scope; a name is where research would look, not a finding about the firm), the artists with the most open histories, the research-term families, the open list (quiet, partly, both; country, artist and dealer selects; sixty rows when narrowed) and a CSV of every open history with the names it carries. The counts beside the artists and the names are open histories of both kinds, so a select lists both kinds; a row of either table clears the other two filters, so the list is exactly what the row counts. The Ledger's dealer filter reads the same main text with the same matcher, so a dealer with "Open in 1933–45" there lists what the Lab counts (`test.js` checks it). The reading also feeds the Ledger (`lstate.prov` filter, `ledgerChip`), the provenance drawer (`labpNote`, with a way back to the Lab), the Clinic (a base rate for the named artist, information only) and the Circle (`labPeriods`, `provThrough`, `provOpen` tokens; the hands instrument adds `holdings` and `ownMedian`). Test hook: `window.__S.labpRead`. Eighteen chosen histories are pinned in `test.js` as regression readings. An independent second reading in October 2026 (48 histories, 45 drawn at random, read blind) agreed with 46 of them; the fixes that followed resolve both disagreements and the corpus cases it ranked most serious, and those are among the pinned readings.

**5. Hands** (`labhRead()`, cached; `src/lab_hands.js`). Reads the entries `labpRead()` keeps on every row (`r.E`). The holder of an entry is the party after its last "to", "by", "for" or "with" outside parentheses (not a date, a price or "by inheritance"; not the partner of a joint account), else the entry's subject; in parentheses a dealer (the Gallery's convention), unless an auction house; an auction entry is a sale; a museum (and the Hermitage, a library, a church, a hospital) an institution; a consignment, an approval or a deposit an agent, through which the owner keeps the work. A holding runs from a dated acquisition to the next dated change of hands through known links, past agents and continuations (an estate, the owner's own trust or foundation, dated or not, `labpOwnFoundation`; the artist's estate is the artist's; a consignment that came back). A holding "by descent" with no year of its own is set apart as a family's. It ended in a sale, with heirs, with the Gallery, with another museum, or otherwise. ## 18. v27: the ocean — the tides, the collectors, the currents and the stones, the whispers, the playbooks; the Net’s new layers; the phone’s zoom (November 2026)

**Why.** The owner asked for the analytical capacity behind the tools: where the market is going and what will rise (sculpture, for example); a mapped-out art ocean with its sunk stones, fishes, tides and temperatures; a zoom into a region, a category or a collector; how money moves through the free ports, who buys what and where; the scandals, with politics and finance connected to the movement of capital; rumours and predictions, monetised by showing where the market is going before it does; the ability to research and to execute a task (the bureaucracy, the restrictions); a value-creation capture mechanism neither house has; and a globe the phone can zoom. Five research agents wrote from briefs (`scratchpad/v27/BRIEF_*.md`, with the people rules in `BRIEF_COMMON.md`); their JSON sits in `data/research/bundle.json` under `v27` (`tides`, `collectors`, `currents`, `whispers`, `playbooks`). `STRATEGY.md` part five is the written case.

**The ocean engine (`src/ocean.js`, pasted at `/*__OCEAN__*/`; five views in More: `tides`, `collectors`, `currents`, `whispers`, `playbooks`).** `renderTides` sorts the tides rising → turning → flat → falling and by strength, draws each as a card (direction glyph, name, strength dots, kind, flag, the folded reading, up to six evidence lines with publisher and date, drivers and risks, the predictions on record, the rumours under a Rumour tag, the artists it carries as dossier links, the places as Net jumps, the watch line, the sources), then the soundings (`ocSoundings`: the share of `RESULTS` money by category and by room, 2021–23 against 2024–26, as paired bars), the temperatures (buttons to the city on the Net), the allocation form (`#tideForm`: sum, horizon, appetite) and the reports. `tideReading({sum, years, risk})` scores the category and region tides by appetite × direction (`low` favours rising and flat, `mid` rising, `high` turning), by strength, by kind (regions at 0.8) and, for a low appetite, discounts thin evidence; takes four (low) or six tides; splits the sum by the scores; lists each with its first evidence line and publisher, the first risk of each, and the sentence that it is a reading, not advice, with the way in and out at 21–38%. `renderCollectors` lists `NET_PLAYERS` with `collector: true` (name as a jump to the Net, seat, wealth tag with its publisher, holds, named works, where, how held, the money, the deals at the top since 2020, the advisers, the documented links with their kind — a sanctions or prosecution tag flagged — and the rumour labelled), filtered by `#collQ`, then the houses of capital (`HOLD_VEHICLES`). `renderCurrents` lists `CURRENTS.cases` newest first (route as an ordered list of from → to with what, via and when; the people as the record states them with role and status; the works; what caught it; the outcome; the lesson for a compliance desk; the places as Net jumps; a button that lights the route on the Net), filtered by kind, then the free ports’ flows and the patterns (each pattern linking its cases). `renderWhispers` lists `WHISPERS.whispers` newest first (kind tag, date, about, the line, the detail, who printed it, what happened, the subjects, the sources), filtered by kind and by `#whQ`, with what is next on top and the forecasters’ records beneath (each call tagged came true / did not / open). `renderPlaybooks` draws each playbook as a `<details>` (jurisdiction, time, cost; the steps with who, time, fee, have-ready, source and flag; what goes wrong; the official links; the tool buttons — the Navigator for an export or import, the Deal Room for a consignment, the vaults for a free port, the Transformation for a loan; print this playbook, which prints one book through `body.print-one`), filtered by jurisdiction, remembering the open book. `playbookFor(words, j)`, `tideFor(words)`, `caseFor(words)` and `collectorFor(words)` find a thing by words (name, then the artists, people, works or places it carries); `ocOpen(view, {q|id|reading|temps|kind})` opens a view on a thing, lighting the card (`ocLit`), and is synchronous because `go()` renders synchronously. `window.__OCEAN = {tides, soundings, reading, collectors, currents, whispers, playbooks, playbookFor, tideFor, caseFor, collectorFor, open}`.

**The Net’s new layers (`src/world.js`).** `NCUR` (the route steps whose ends resolve to cities, as `glbArcPts` arcs), `NSTONE` (one stone per case, at the last resolved `to` of its route or its last place) and `TEMP` (city → temperature) are prepared with the players and the flows. `wdRouteKey(s)` extends `wdCityKey` with `WD_ROUTE_SEATS`: a country, an island, an offshore seat, an institution or a spelling the research wrote (‘Switzerland’ → Geneva, ‘BVI’ → Road Town, ‘Delaware’ → Wilmington, ‘Monte Carlo’ → Monaco, ‘Zürich’ → Zurich, ‘Hobby Lobby’ → Oklahoma City); a route end that names only a shell, a person or ‘offshore accounts’ draws no arc and stays in the card’s list.
